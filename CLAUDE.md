# kudab

Инфра-репо. Сервисы лежат сабмодулями в `services/`, у каждого свой CLAUDE.md. Правила ниже общие для всех.

## Комментарии в коде

Комментарий нужен, только если без него следующий правщик ошибётся: неочевидная причина, ловушка, смысл пустого значения (null, 0, пустой массив), связь «меняешь здесь, поменяй и там».

- Обычный комментарий одна-две строки, докблок до четырёх. Строки `@param`/`@return` с формой массива не в счёт.
- Замеры, даты, историю правки («раньше было»), кто решил, как нашли баг, какие варианты отвергли — всё это в сообщение коммита. В коде этого нет.
- Починил баг — в коде остаётся починенный код. Рассказ о баге только в коммите.
- Не пересказывать соседнюю строку и имя функции. Одна причина живёт в одном месте, в остальных хватит «см. имяМетода».
- Писать простым русским, как объяснил бы знакомому, который не читал код: что делает и зачем. Понятнее важнее, чем короче.
- Без жаргона и англицизмов: не «claim до выдачи, чтобы поллер не запостил дважды», а «сначала помечаем запись взятой, чтобы пост не ушёл дважды». Имя из кода — только когда называешь конкретный метод, поле или константу, и тогда в обратных кавычках. Без своих словечек вроде «ручка», «дверь», «сито».
- Без капса для нажима (одно слово-оператор НЕ, ДО, ТОЛЬКО можно), без «ровно», «именно», «честно», «намеренно», без морали в конце. «Не X, а Y» только когда X — та самая ошибка, которую правщик сделает первой.
- Записки для следующей сессии — в память или в доки задачи, не в код.
- Сомневаешься, нужен ли комментарий, — не нужен.

Раздутый комментарий не пропустит хук `.claude/hooks/comment-guard.py`. Если он отказал, сократи, а не обходи. Чистка старых комментариев — скилл `kudab-comments`.

## Тесты

- Тест пишется на поведение, которое может сломаться незаметно. Одна регрессия — один тест, а не тест на каждый пункт коммита.
- Не нужны тесты на константу или литерал, на текст шаблона слово в слово, на то, что делает сам Laravel, и на то, что уже проверяет соседний тест.
- Перед новым тестом грепнуть имя класса по `tests/`: файл про него может уже быть, тогда дописывать туда и брать его заготовки.
- Тест должен уметь упасть. Мысленно убери правило, которое он охраняет: тест покраснеет? Если нет, он ничего не охраняет.
- Случаи с одинаковым телом, которые отличаются только данными, — один тест с data provider.
- Докблок над тестом не нужен, имя теста уже говорит, что проверяется. Одна строка у странных данных фикстуры — можно.
- Сколько тестов добавлено, в коммит и отчёт не писать.

Запуск: api — `make test` или `make test-filter FILTER=…`, парсер — `make test-parser`. `php artisan test` в api напрямую сносит рабочую базу. Чистка лишних тестов — скилл `kudab-tests`.
