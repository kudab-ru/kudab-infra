# Чистка лишних тестов

Удалить тест — снять защиту. Поэтому здесь планка строже, чем у комментариев: каждое удаление доказывается открытием файлов, а сомнение решается в пользу теста. На разборе сентября 2026 скептики опровергли 17 предложений из 122 и ещё 27 поправили.

Лишних тестов обычно немного: из 1900 кейсов api и парсера удалить без потери защиты можно около сотни, ещё около двухсот схлопываются в провайдеры. Основной мусор в тестах — комментарии, их чистит скилл `kudab-comments`.

## Когда тест лишний

1. **Дубль по тому же пути кода.** Второй тест подаёт тот же вход в ту же ветку и проверяет то же. Проверка: можно ли сломать код так, чтобы упал только этот тест? Если нельзя, он дубль.
2. **Не может упасть.** Мысленно убери правило, которое тест охраняет. Если тест останется зелёным, он ничего не охраняет. Частые причины: фикстура делает результат неизбежным, ожидаемое совпадает с тем, что вернула бы неправильная ветка, `assertTrue(true)`, `assertIsArray` там, где и сломанный код отдаёт массив, выборка захватывает сам проверяемый объект.
3. **Проверка литерала.** Тест сверяет константу, дефолт DTO или имя гарда с тем же литералом, записанным в коде, или повторяет таблицу-константу построчно.
4. **Копия формулы.** Ожидаемое значение тест считает той же формулой, что и код, или вовсе не вызывает класс под тестом.
5. **Мёртвая цель.** Метод или константу в `app/` никто не читает (`grep`), а тест их охраняет и мешает удалить.
6. **Проверка фреймворка.** Касты Eloquent, `TrimStrings`, welcome-страница `ExampleTest`.
7. **Серия одной формы.** Три и больше теста с одинаковым телом, отличаются только литералами входа и ожидания. Это не удаление, а слияние в data provider.
8. **Одна подготовка, разрезанная на тесты.** Тот же arrange и тот же act, разные стороны результата. Сливать в один тест.
9. **Гейт авторизации в каждом файле.** 401/403 для ручки, у которой middleware висит на группе. Лучше один тест по `Route::getRoutes()`: каждый маршрут `api/admin/*` несёт `auth:sanctum` и роль. После него точечные проверки уходят.
10. **Мёртвые фикстуры.** Файлы в `tests/Fixtures`, на которые не ссылается ни один тест. Ссылка из команды, которая их пишет, не в счёт.

## Когда трогать нельзя

- **Покрытие случайное.** Второй тест покрывает случай только потому, что так вышла его фикстура. Удаляя «дубль», сначала перенеси случай явно в выживший тест.
- **Разные плечи одного выражения.** Два входа дают сейчас одно значение через разные ветки тернарника или `??`. Это две ветки, а не дубль.
- **Слабый против явного.** Из пары удалять тот, где проверка случайна, и оставлять тот, где она предмет теста. Смысл из имени удалённого перенести в имя выжившего («без многоточия»).
- **Вечнозелёный, но единственный.** Если правило живое и больше ничем не проверено, тест чинят (фикстура, при которой он может покраснеть), а не удаляют.
- **Unit не заменяет feature.** Тест репозитория не отменяет тест параметра ручки: контроллер может потерять ключ по дороге (`validate()` отдаёт только ключи с правилами).
- **Разная подготовка.** В провайдер сводить только тесты с одинаковым телом. Если случаю нужна своя подготовка или своя проверка, оставлять отдельно. Два коротких теста лучше провайдера с `if` внутри.
- **Положительный контроль.** Прежде чем убирать «копию happy-path», проверь, не держит ли её пара данных отрицательные тесты того же файла от прохождения вхолостую.
- **Сверка двух мест.** Тест через Reflection сравнивает константу с константой другого класса: он проверяет, что два места не разошлись. Удалять только вместе с заменой литерала ссылкой.
- **Код эпохи владельца** (до мая 2026). Менять форму (провайдер, склейка) только если он попросит.

## Порядок работы

1. **Границы.** `git status` сервиса. Тесты с чужими незакоммиченными правками не трогать.
2. **Поиск.** Агенты по файлам тестов. На каждое предложение — файл, тест, строка и доказательство: для дубля имя второго теста и строка его проверки, для вечнозелёного правило, которое можно убрать без красного теста, для мёртвой цели вывод `grep`.
3. **Скептик.** Второй агент на каждую находку пытается её опровергнуть по списку «Когда трогать нельзя». Прошедшее без опровержения идёт в работу, остальное в отчёт.
4. **Правка.** Удаления и слияния руками, по одному файлу, с чтением теста целиком. Вечнозелёный тест с живым правилом чинить, а не удалять.
5. **Прогон.** api `make test` (или `make test-filter FILTER=…` по файлу), парсер `make test-parser`. `php artisan test` в api напрямую сносит рабочую базу. Код 255 без красных тестов у парсера — предел памяти, а не тест.
6. **Проверка, что защита осталась.** Для каждого слияния и починки: сломать правило в коде на минуту, увидеть красный тест, вернуть. Хотя бы на выборке.
7. **Коммит.** Отдельный от кода, `git add` по файлам. В сообщении что убрано и почему одной строкой на вид, без подсчёта тестов.

## Признаки для поиска

```bash
grep -rn 'assertTrue(true)' tests/
grep -rn 'ReflectionClass\|ReflectionMethod\|setAccessible' tests/
grep -rln 'ExampleTest\|A basic test example' tests/
grep -rn 'function test_name\b\|test_default_diagnostics' tests/
# фикстуры, чьё имя нигде не упомянуто. Пометка «каталог» значит, что каталог
# упомянут: проверь, не читает ли тест его целиком по маске (так устроены golden)
find tests/Fixtures -type f | while read f; do
  grep -rqF "$(basename "$f")" tests app --exclude-dir=Fixtures && continue
  grep -rqF "$(basename "$(dirname "$f")")" tests app --exclude-dir=Fixtures && echo "$f  (каталог)" || echo "$f"
done
```
