## 1. Перед выкаткой: снять состояние прода (только чтение)

Всё, что ниже, ничего не меняет. Выполнять на сервере.

```bash
# 1.1 Каналы: включён, есть ли владелец и город, какие настройки
docker compose -f docker-compose.yml -f docker-compose.prod.yml exec -T kudab-db \
  psql -U kudab -d kudab -Atc "
select b.id, c.username, b.enabled, (c.telegram_user_id is not null) as has_owner,
       c.city_id, b.settings
from telegram.chat_broadcasts b join telegram.chats c on c.id = b.chat_id order by b.id;"
```

Смотреть в `settings` три ключа:

- **`feed_limit`** — если его НЕТ, канал после выкатки перейдёт с «одного поста
  в полёте» на семь. Это самое дорогое из того, что можно проглядеть;
- **`slots`** — часы публикации. Если они разошлись с тем, что реально стоит в
  ленте (см. 1.2), сначала решить это, а потом выкатывать;
- **`ai_text`** — выключен, значит канал НЕ будет писать ни анонсы событий, ни
  текст подборки: посты уйдут описанием из парсера.

```bash
# 1.2 Лента: на каких часах она реально стоит
docker compose -f docker-compose.yml -f docker-compose.prod.yml exec -T kudab-db \
  psql -U kudab -d kudab -Atc "
select broadcast_id, (publish_at at time zone 'Europe/Moscow')::time as msk, count(*)
from telegram.chat_broadcast_items
where status in ('pending','planned') and publish_at is not null
group by 1,2 order by 1,2;"

# 1.3 Очередь ожидания: записи без дня держат ячейку feed_limit
docker compose -f docker-compose.yml -f docker-compose.prod.yml exec -T kudab-db \
  psql -U kudab -d kudab -Atc "
select broadcast_id, count(*) filter (where publish_at is null) as no_day,
       count(*) filter (where publish_at is not null) as with_day
from telegram.chat_broadcast_items
where status in ('pending','planned') group by 1 order by 1;"

# 1.4 Какой код там сейчас
git rev-parse HEAD && git submodule status
```

```bash
# 1.5 Метрика: без этих ключей прибор отклика молча не заработает
grep -E '^YANDEX_METRIKA_COUNTER|^YANDEX_OAUTH_TOKEN' .env
```

Ключей нет — не беда: `broadcast:collect-clicks` честно скажет «Метрика не
настроена» и выйдет без ошибки. Всё остальное работает без неё.

## 2. Бэкап — глазами, а не на веру

```bash
make backup
ls -lh backups/ | tail -3
```

**Смотреть на размер файла.** Откат (`make rollback`) сносит том базы
(`down -v`) ДО того, как проверит наличие дампа: пустой или обрезанный бэкап
означает потерю базы, а не откат.

---

## 3. Выкатка

```bash
make prod-deploy
```

Пять шагов: сборка → ожидание базы → миграции → **заполнение связи
«пост → события»** → one-shot задачи парсера. Четвёртый шаг обязателен и
прерывает деплой при провале: все четыре слоя анти-дублей читают эту связь, а
миграция создаёт таблицу пустой. Между миграцией и заполнением защита от
повторов не видит ни одного занятого события — канал начал бы повторять
опубликованное молча и без единой ошибки.

## 4. Сразу после выкатки

```bash
# 4.1 Связь заполнена полностью (обе строки должны быть нулями)
docker compose -f docker-compose.yml -f docker-compose.prod.yml exec -T kudab-api \
  php artisan broadcast:links:backfill --check

# 4.2 Новые команды в расписании
docker compose -f docker-compose.yml -f docker-compose.prod.yml exec -T kudab-api \
  php artisan schedule:list | grep -E "fill-feed|sweep-queue|collect-clicks|enqueue-digests"

# 4.3 Что сделает наполнитель — БЕЗ записи
docker compose -f docker-compose.yml -f docker-compose.prod.yml exec -T kudab-api \
  php artisan broadcast:fill-feed --dry-run

# 4.4 Что снимет уборщик очереди — без записи
docker compose -f docker-compose.yml -f docker-compose.prod.yml exec -T kudab-api \
  php artisan broadcast:sweep-queue --dry-run
```

Обе команды с `--dry-run` не пишут ничего: наполнитель прогоняет настоящий код
в транзакции и откатывает её. По их выводу видно заранее, что случится в
ближайший час.

## 5. Что изменится само, без вашего участия

**В первый час:**

- `broadcast:fill-feed` закроет все свободные слоты горизонта. На стенде по
  боевой ленте это было **15 постов за один прогон** — проверьте своим
  `--dry-run` (4.3) ДО того, как оно случится. Раньше ленту наполняли только
  две кнопки в админке, теперь это делает расписание;
- `broadcast:sweep-queue` снимет из очереди ожидания записи, чьё событие уже
  началось. Они и так были мертвы, но держали ячейку `feed_limit`.

**В первый день:**

- посты, стоящие ПОЗЖЕ начала своего события, доставка снимет с причиной
  «событие уже началось». Это новое правило, и оно жёстче прежнего: раньше
  такой пост уходил в канал и звал на то, что уже идёт;
- подбор событий требует **шесть часов форы**: анонс за час до начала больше
  не ставится;
- анонсы событий пишет модель перед публикацией (если `ai_text` включён), а
  подборка недели — в момент выхода, с придержкой на несколько минут;
- ссылки в постах получили метку `utm_content`, и раз в сутки
  `broadcast:collect-clicks` будет складывать переходы в ленту.

## 6. Решения, которые придётся принять руками

1. **Вечерний слот.** Если `settings.slots` и реальные часы ленты разошлись
   (1.1 против 1.2) — нажать в админке **«Пересобрать неделю»**, НЕ
   «Разбавить». Пересборка сначала обнуляет дни и раскладывает заново;
   «Разбавить» просто доложит посты в новые часы поверх старых.
2. **`ai_text`.** Выключен — канал постит сырые описания из парсера, и подборка
   выйдет без живого текста. Один вызов модели стоит ≈$0,005.
3. **Подборка недели.** Рубрика включается ключом `digest_weekday` в настройках
   канала. Нет ключа — рубрики нет вовсе.
4. **`fill_lead_days`.** Если не хотите видеть расписанные две недели вперёд —
   поставьте поздний слот на заполнение за сутки. Настройка в админке, «Поздний
   слот заполнять».

---

## 7. Если что-то пошло не так

- **Канал начал постить лишнее** — выключить его в админке (`enabled`), это
  останавливает доставку немедленно; разбираться потом.
- **Откат кода** — `make rollback`, но помните: он делает `down -v` ДО проверки
  дампа. Перед ним ещё раз посмотрите на размер файла в `backups/`.
- **Откат миграций не нужен**: все шесть аддитивны, старый код просто не видит
  новых колонок.

---

## 8. Чего НЕ делать

- **Не запускать `php artisan test` на проде** — набор идёт через
  `RefreshDatabase` и снесёт базу. Тесты гоняются только из инфры целями
  `make test` / `make test-parser` на отдельной базе.
- **Не жать «Разбавить» вместо «Пересобрать неделю»** при смене часов (см. 6.1).
- **Не оставлять `links:backfill` провалившимся**: анти-дубли слепы, пока связь
  пуста.
